版本：v1.0
项目名称：老实人
文档类型：HarmonyOS Client Technical Design
当前阶段：V1 正式开发设计

==================================================
0. 文档目的
==================================================

本文件用于确定“老实人”V1 HarmonyOS 客户端的技术边界、页面结构、交互模型、网络层、本地状态、文件/语音/分享、流式 Agent 交互、Push 和与 FastAPI 的联调方式。

本文件重点回答：

1. HarmonyOS 客户端负责什么；
2. ArkTS / ArkUI 如何组织代码；
3. App 有哪些主要页面；
4. Chat 如何与 Agent Run 对接；
5. 如何处理流式回复；
6. 如何上传图片、PDF、Word、PPT；
7. 如何接收其他 App 分享；
8. 如何接入语音输入；
9. Today / Things / Timeline 如何展示；
10. 如何实现 Push；
11. 本地缓存什么、不缓存什么；
12. 如何处理断网、重连、Agent interrupt；
13. 如何保证客户端不复制后端业务逻辑；
14. V1 应按什么顺序实现。

核心原则：

HarmonyOS Client
=
用户体验层
+
系统能力入口
+
后端 Agent 的客户端

而不是：

第二套 Agent Backend。

1. 客户端总体定位
==================================================

老实人的“智能核心”继续在后端：

Python
+
FastAPI
+
LangGraph
+
Executive Agent
+
Personal State
+
Memory
+
Automation
+
Tools


HarmonyOS 客户端主要负责：

- 界面；
- 用户输入；
- 消息展示；
- 文件选择；
- 图片选择；
- 语音输入；
- 其他 App 分享接收；
- Today / Things / Timeline 浏览；
- 本地轻量缓存；
- 网络状态；
- Agent Run 状态展示；
- interrupt / confirmation；
- Push；
- Deep Link；
- 系统权限；
- 客户端生命周期。


禁止：

把 Agent 决策逻辑复制到 ArkTS。

例如：

不要在客户端自己判断：

“这句话是不是要更新 deadline？”

正确：

ArkTS
→ FastAPI
→ Executive Agent
→ Tool / Policy
→ Result
→ ArkTS 展示

==================================================
5. UIAbility
==================================================

V1 采用 Stage 模型。

主要入口：

EntryAbility


EntryAbility 负责：

- App 启动；
- Window 创建；
- 初始化应用级依赖；
- 处理 Want；
- 接收可能的分享 / Deep Link；
- 恢复客户端轻量状态；
- 注册必要系统能力。


EntryAbility 不负责：

- Agent 推理；
- 业务状态判断；
- 直接操作 Personal State 数据库。

==================================================

- 从 Push 进入对应 Chat。

13. Agent Run 客户端模型
==================================================

每次用户发送消息：

Message
↓
POST /api/v1/runs
↓
run_id
↓
连接 stream
↓
接收：
assistant.delta
status.updated
interrupt.required
run.completed
run.failed


客户端必须把：

Message
和
Run

分开。


例如：

用户消息已发送成功，
Run 后续可能：

RUNNING
WAITING_USER
FAILED
COMPLETED

==================================================
15. Agent 流式输出
==================================================

客户端抽象：

AgentStreamClient


而不是：

ChatPage 直接解析 SSE。


接口概念：

connect(runId, listener)
disconnect(runId)


listener：

onRunStarted
onAssistantDelta
onStatusUpdate
onInterrupt
onCompleted
onFailed


这样底层未来可以：

SSE
→ WebSocket

而不改 Chat UI。


==================================================
16. V1 Streaming 方案
==================================================

优先：

FastAPI
→ HTTP Streaming / SSE
→ HarmonyOS Client


但正式真机联调时必须验证：

- 长连接稳定性；
- 网络切换；
- 后台/前台；
- 连接断开；
- chunk 读取；
- 代理环境；
- 服务端 timeout。


如果 SSE 在当前 SDK / 网络链路下实现复杂：

切换：

WebSocket


后端 Run 模型保持不变。


核心原则：

Transport
≠
Agent Runtime。

==================================================

==================================================

==================================================
20. App 退出与 Run
==================================================

用户退出 Chat：

不能理解为：

Cancel Agent Run。


客户端：

- 断开 stream；
- 记录 run_id；
- 页面可销毁。


Backend Run：

继续执行。


用户返回：

GET /runs/{id}

如果：

RUNNING
→ reconnect stream

WAITING_USER
→ 恢复 Interrupt UI

COMPLETED
→ 加载最终消息

FAILED
→ 展示失败状态

==================================================
24. 图片上传体验
==================================================

选图后：

Composer 显示：

thumbnail
filename / type
remove button


发送前：

可以先上传 Source，
也可以发送时统一上传。


推荐：

先 upload
→ obtain source_id
→ user sends run


原因：

Agent Run 不需要等待整个文件上传流程后才创建不稳定状态。

==================================================
31. 本地状态管理
==================================================

客户端状态分三类：

A. UI State

例如：

当前 Tab
输入框内容
弹窗状态
loading


B. Session State

例如：

currentThreadId
currentRunId
lastVisitedThing


C. Cached Server Data

例如：

Thing summaries
recent messages
attention items


不要把：

Personal State 的唯一权威版本

只放客户端。


==================================================
32. ArkUI 状态
==================================================

页面 UI 状态：

使用 ArkUI 状态管理能力。


原则：

页面状态就近管理。

跨多个页面真正共享：

再提升到应用级 Store。


不要一开始：

创建一个巨大 GlobalStore
把所有对象都塞进去。


==================================================
33. Preferences
==================================================

HarmonyOS Preferences 适合：

轻量 Key-Value。


V1 用于：

- API environment；
- user preferences；
- notification preference；
- last thread id；
- theme；
- onboarding flag；
- small client settings。


不用于：

- 完整消息历史；
- 所有 Thing；
- 大文件；
- 大型 JSON 数据库。


==================================================
34. Local Cache
==================================================

如果 V1 需要离线浏览：

可以使用 ArkData 本地数据库。


但第一阶段：

不急于把服务器所有表复制到手机。


推荐最小缓存：

- 最近 Thread；
- 最近消息；
- Thing summary；
- Attention summary；
- pending upload metadata。


先做：

online-first
+
graceful cache


不是：

full offline-first sync system。


==================================================
35. Server Source of Truth
==================================================

以下数据以 Backend 为准：

Thing
Task
Deadline
Timeline
Memory
Automation
Run State


客户端：

可以乐观显示，
但最终必须接受 Server Result。


例：

用户勾选 Task DONE：

UI：
立即显示完成（optional optimistic）

Backend：
PATCH task

如果：

409 VERSION_CONFLICT

Client：

回滚 / refresh
+
提示当前数据已变化。

- auth；
- timeout；
- JSON decode；
- error normalization；

==================================================

因为当前一个人开发，

→ Application 原子用例
→ PostgreSQL / Repository
→ Product API
→ HarmonyOS 结构化功能
→ Agent Tool Adapter
→ Executive Agent

客户端工程壳可以尽早初始化；
Agent 接入必须建立在可独立测试的 Application / Domain 能力之上。


Slice 1：

ArkTS Chat
↓
FastAPI /runs
↓
LangGraph
↓
简单 Agent Reply


Slice 2：

↓
state.update_task
↓
Thing UI


Slice 3：

Share PDF
↓
Source
↓
document Tool
↓
Agent


Slice 4：

Automation
↓
Push


每一条都是：

→ 后端
→ Agent
→ 数据
→ 手机


这样更早发现：

产品和平台集成问题。

110. 官方设计依据（截至 2026-08）
==================================================

1. HarmonyOS 应用开发导读
https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/application-dev-guide

依据：
HarmonyOS SDK 以 Kit 提供应用框架、系统、媒体、应用服务等能力；
Ability Kit 与 ArkUI 属于应用框架核心能力。


2. ArkTS 官方介绍
https://developer.huawei.com/consumer/en/arkts/

依据：
ArkTS 是 HarmonyOS 生态应用开发语言；
保持 TypeScript 基础语法风格并强化静态检查；
支持声明式 UI、状态管理和并发能力。


3. HarmonyOS SDK / Develop
https://developer.huawei.com/consumer/en/harmonyos/develop/

依据：
官方列出 Ability Kit、ArkData、ArkTS、ArkUI、Core File Kit、Push Kit、Calendar Kit 等能力。


4. ArkUI Navigation / NavDestination
https://developer.huawei.com/consumer/en/doc/harmonyos-guides/arkts-navigation-navdestination

依据：
Navigation / NavDestination 用于声明式页面导航及子页面管理。


5. File Picker
https://developer.huawei.com/consumer/en/doc/harmonyos-references/js-apis-file-picker

依据：
Core File Kit 提供 DocumentViewPicker、AudioViewPicker；
官方已标明旧 PhotoViewPicker deprecated，并推荐 photoAccessHelper.PhotoViewPicker。


6. HarmonyOS 应用数据持久化 / Preferences
https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/data-persistence-by-preferences

依据：
Preferences 面向轻量 Key-Value 持久化，适合用户个性化设置等小数据场景。


7. HarmonyOS 数据存储方案选择
https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-local-database-management-38

依据：
HarmonyOS 提供 LocalStorage、AppStorage、PersistentStorage 及 ArkData 多种存储方案，应按数据类型和访问模式选择。


8. Network APIs
HarmonyOS API Reference:
@ohos.net.http
@ohos.net.webSocket
Remote Communication Kit

https://developer.huawei.com/consumer/en/doc/harmonyos-references/arkts-api

依据：
HarmonyOS 官方提供 HTTP、WebSocket 和 Remote Communication Kit 数据请求能力。


9. Push Kit
https://developer.huawei.com/consumer/cn/hms/huawei-pushkit

依据：
Push Kit 提供云端到 HarmonyOS 终端的消息推送能力。


10. HarmonyOS SDK Push Kit
https://developer.huawei.com/consumer/cn/sdk/push-kit/

依据：
Push Kit 是当前 HarmonyOS SDK 应用服务能力之一。


11. Share Kit / 系统分享
HarmonyOS 文档中心：
https://developer.huawei.com/consumer/cn/doc/

依据：
Share Kit 提供文本、图片、视频等跨应用分享能力；
Ability Kit 的 Want 同时是应用组件间信息传递载体。
