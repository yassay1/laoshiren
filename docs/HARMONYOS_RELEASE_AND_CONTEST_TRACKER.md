# 老实人 HarmonyOS 上线与活动追踪

> 维护目的：记录老实人 HarmonyOS 客户端的上线状态、华为平台要求、活动资格和代码证据。
> 
> 状态基准：2026-09-19。外部活动规则以官方页面最新版本为准；本文件中的网页内容只作为项目追踪快照。
> 
> 当前工作基线：从零开始办理上线与活动事项；未有证据的事项一律视为“未开始”。

## 0. 状态规则

状态只使用以下四种：

- `未开始`：尚未办理或尚未实施。
- `进行中`：已经开始，但还没有完成证据。
- `已完成`：有平台记录、代码路径、测试结果、截图或审核记录。
- `阻塞`：明确知道下一步，但被账号、权限、设备、审核或外部服务阻挡。

## 1. 当前结论

这不是传统意义上的比赛，而是最符合当前项目形态和时间窗口的华为官方应用上架激励计划：

- 报名：2026-04-15 至 2026-09-25。

## 2. 项目代码现状

### Backend

- V2.2 Phase 0–8 核心能力已完成。
- FastAPI 模块化单体，PostgreSQL/pgvector 为 durable truth，Redis 仅作协调与唤醒。
- Agent 为 Single Executive LangGraph，已有 Run、DurableJob、Tool Ledger、HITL、SSE、Memory、Automation、Identity 等能力。
- 当前生产缺口：Huawei 生产 JWKS、Huawei Push Kit、S3、账号数据彻底 purge、完整 RELATIVE/CONDITION 调度、OpenTelemetry 等。

### HarmonyOS 客户端

- C1–C6 已完成：客户端传输层、Provider 边界、Things/Today/Tasks/Me 读取链路、设备/Session 基础、共享依赖注入、Mock 登录状态、DTO/SSE 合同收敛。
- C7 待完成：官方 Huawei Account、Push、Reminder 适配，以及官方文档、权限、AGC 配置和真机/云真机证据。
- C8 进行中：模拟器流程、真机流程、签名、发布验证、仓库 Secret 扫描。
- 当前工作区有未提交的客户端和 Huawei 登录改动，不能把它们等同于已发布版本。

## 5. 执行顺序

### 阶段 A：账号与资格（先做）

1. 注册/实名认证华为开发者账号。
2. 创建 AGC 应用，先冻结最终包名和应用名称。
3. 开通商户服务，并确认收款主体。
4. 报名“鸿蒙应用开发者激励计划 2026”。
5. 将每一步的截图、编号和日期填入本文件。

### 阶段 B：可提交版本

1. 配置签名证书和 Profile。
2. 清除 localhost、固定 Bearer Token、Mock 登录等生产依赖。
3. 完成生产 Huawei Account 登录，至少验证登录、刷新、退出、失效恢复。
4. 完成 Chat、SSE、Today、Things、Tasks、Me 的最小闭环。
5. 生成 release 包，做真机或云真机验证。

### 阶段 C：审核与正式上架

1. 准备隐私政策、权限说明、第三方 SDK 清单、图标、截图和应用介绍。
2. 提交华为应用市场审核。
3. 每次驳回都记录原因、修改文件和重新提交日期。
4. 只有审核通过并正式上架后，才把“正式上架”记为已完成。
5. 记录首次正式上架时间，作为激励计划的重要证据。

### 阶段 D：上架后维护

1. 记录活动后台有效设备数、评分和激励状态。
2. 维护应用在架状态与线上稳定性。
3. 记录版本发布、崩溃、审核、用户反馈和修复结果。

## 7. 维护规则

每次完成任务后更新：

1. 本文件的清单和状态；
2. `docs/CURRENT_IMPLEMENTATION.md`（若代码现状变化）；
3. `progress.md`（过程证据、测试、失败原因）；
4. 若官方规则变化，在“当前结论”中补充日期和官方链接，不覆盖历史判断。

所有“已完成”必须附代码路径、测试命令、截图、后台记录或审核记录之一；没有证据只能记为“进行中”或“待确认”。
